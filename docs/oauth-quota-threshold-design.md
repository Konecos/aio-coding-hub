# OAuth 剩余额度阈值控制设计

状态：已实现。

## 目标与范围

按 OAuth 供应商设置剩余百分比阈值。额度达到阈值后，网关跳过该供应商并继续选择其他供应商；额度恢复后自动恢复参与路由。

控制对象是通过本应用网关分配的新请求。已经发送的请求和正在输出的流继续执行。该机制依赖上游额度快照，不能精确预留单次请求消耗，也不能控制同一账号在其他客户端的消费。

第一版使用供应商级规则，分别配置短窗、长窗阈值；不增加全局继承、模型级阈值或独立恢复阈值。

## 实现位置

- `src-tauri/src/domain/provider_oauth_limits.rs`：持久化原始精度百分比，统一判断耗尽、阈值命中和待确认；快照写入通过版本检查防止迟到结果覆盖。
- `src-tauri/src/app/oauth_quota_service.rs`：共享额度获取、Token 刷新、适配器解析及快照写入；命令层保留薄包装。
- `src-tauri/src/app/oauth_quota_runtime.rs`：后台调度、共享查询锁、并发限制、退避和供界面读取的缓存状态。
- `src-tauri/src/gateway/proxy/handler/failover_loop/prepare/`：普通请求和 CX2CC 源供应商门禁，保护跳过不计入熔断失败。
- `src-tauri/src/gateway/responses_ws/ingress.rs`：每个新推理请求重新经过网关链路，并将本地网关错误转换为可识别的 WebSocket 错误事件。
- `src-tauri/src/gateway/oauth/adapters/gemini.rs`：保持每个桶的百分比与重置时间配对，按窗口内最小值聚合，只有次数时保持百分比未知。
- `src/query/oauthQuotaStates.ts`、供应商编辑窗口、首页及供应商卡片：读取后端缓存决策并展示保护配置和状态。

## 配置与界面

在 OAuth 供应商编辑窗口的连接区域下面增加“剩余额度保护”：

```text
剩余额度保护
短窗剩余 ≤ [ 10 ] % 时暂停使用     [启用]
长窗剩余 ≤ [  5 ] % 时暂停使用     [启用]

任一已启用的窗口达到阈值后，自动切换供应商。
额度恢复后自动恢复；无法确认额度时暂时跳过。
```

- 两个窗口分别开启，默认均关闭。10% / 5% 是用户开启时的初始建议值，不自动对已有供应商生效。
- Codex / Claude 显示“5 小时”和“每周”；其他适配器使用其实际窗口名称，未确认的窗口显示“短窗 / 长窗”，不将 Gemini 的窗口固定解释为 5 小时 / 每周。
- 输入整数，范围 0–99。0 表示仅在额度为零时拦截，关闭表示不设置该窗口的主动阈值。实际耗尽拦截仍独立存在。
- 没有该窗口，或适配器只能返回次数且没有总额 / 比例时，禁用对应配置并说明原因。临时获取失败与“不支持百分比”分别展示。
- 编辑已有配置时，即使额度接口临时失败，也保留已保存规则，允许用户关闭保护。
- 保存后立即重新判断状态。调高阈值可立即暂停，调低阈值在有效快照满足条件时立即恢复。

供应商卡片及首页额度行展示后端计算的状态、窗口、剩余值、阈值、最后成功更新时间及预计重置时间：

| 状态 | 示例文案 |
| --- | --- |
| 可用 | 5 小时剩余 43%，停止阈值 10% |
| 阈值暂停 | 额度保护：5 小时剩余 8% ≤ 10%，预计 18:30 重置 |
| 待确认 | 额度待确认，暂时跳过；上次成功更新于 12:00 |
| 实际耗尽 | OAuth 额度已耗尽，等待重置 |

保留“刷新额度”入口。额度刷新成功只更新门禁结果，不自动清除其他原因造成的熔断。现有 Codex 手动重置额度入口保持手动操作，成功后重新读取额度；阈值保护不自动消耗重置次数。

## 判断与恢复规则

每个已配置窗口独立判断，使用原始精度的剩余百分比：

```text
窗口命中 = remaining_percent <= stop_threshold_percent
暂停供应商 = 任一窗口命中，或实际额度耗尽
```

例如短窗阈值 10%、长窗阈值 5%：短窗 10%、长窗 80% 时暂停；短窗 11%、长窗 4% 时仍暂停；只有两窗均高于各自阈值才能恢复。

决策顺序：

1. 保留供应商启用、认证及已有路由约束。
2. 判断实际额度耗尽。
3. 对已配置阈值的窗口判断数据有效性及阈值。
4. 通过后继续现有消费金额上限等检查。

规则细节：

- 仅当 `auth_mode = oauth` 时执行主动阈值保护，配置不修改 `enabled`、优先级或熔断状态。
- 有效快照中的任一窗口命中即可暂停；另一窗口未知不会掩盖已知的暂停原因。
- 开启规则但没有快照、受控窗口缺少百分比、快照过期或数据库不可读时，返回“额度待确认”并暂时跳过，不默认为可用。这是第一版确定的保护策略；未开启规则的供应商保留当前行为。
- 成功刷新后全部受控窗口高于阈值，才能恢复。刷新失败不能把之前的暂停改为可用，不能覆盖最后成功快照。
- 到达某窗口重置时间后，该窗口旧快照失效并触发刷新，不直接假定额度已恢复。其他仍未重置的受控窗口继续参与判断。
- 多窗均命中时，展示全部原因；已知重置时间中的最晚时间只是预计解除时间，恢复仍以刷新结果为准。有窗口重置时间未知时，不承诺确定恢复时间。
- 没有重置时间的主动阈值暂停持续到刷新确认、修改规则或关闭保护；不能复用当前五分钟耗尽冷却来自动解除主动保护。
- 获取额度的认证、连接或限流错误归类为刷新错误，不把普通请求的所有 429 都写成“剩余 0%”。保留已有真实耗尽识别路径。
- 第一版不做额外迟滞；若上游额度在阈值附近波动，按最新有效快照判断。

## 后端刷新与请求链路

获取额度逻辑已下沉为共享应用服务，手动刷新和后台刷新复用同一查询路径。手动重置保留原有兑换流程，其额度确认复用解析、版本校验和快照写入，并与刷新操作共享供应商锁及全局并发限制。

网关启动时立即刷新已启用且配置保护的 OAuth 供应商；之后第一版每 60 秒刷新，成功快照有效期 120 秒。使用当前决策时间判断有效期及重置时间，避免长请求沿用请求创建时间。

- 保存保护配置、重新授权或账号变化时触发刷新；账号变化需要清除旧账号快照。
- 受控窗口重置时提前安排确认，不必须等待完整轮询周期。
- 单个供应商同一时间最多一个额度查询，手动 / 后台 / 重置操作共享去重机制；全局并发限制建议为 2。
- 出错后建议按 60 / 120 / 300 秒退避，加入抖动；上游提供有效 `Retry-After` 时遵守。用户手动刷新仍受并发及上游限流约束。
- 只刷新已启用且配置保护的供应商；因额度保护被暂停的供应商仍需刷新，用户手动禁用的供应商退出自动轮询。
- 网关停止时终止后台任务，重启后按持久化快照有效性重新判断。
- 请求路由只读取本地状态；数据未知或过期时跳过，由每 5 秒检查一次的后台调度完成刷新，不在每个推理请求前查询上游额度接口。
- 快照成功更新及配置变更后向前端通知失效，前端从后端读取状态；状态展示不能自行用显示文本推断。

正常情况下，阈值命中被发现可能滞后约一个刷新周期，加上上游自身的统计延迟。高并发、长请求和其他客户端用量可能继续降低剩余额度，因此界面应明确这是基于最近额度数据的请求分配保护。

所有代理入口都需要检查：普通 HTTP、流式 HTTP、Responses WebSocket 的每个新推理请求，以及 CX2CC 使用源 OAuth 供应商的路径。建立 WebSocket 连接时的一次检查不足以保护后续请求；阈值命中后拒绝该连接上的后续新推理请求，已开始的响应继续输出。已有连接无法透明切换供应商时返回明确错误，由客户端重连进入正常路由。

被跳过的供应商不消耗上游尝试次数，不计为上游失败，不触发熔断。仍按现有优先级寻找其他可用供应商；全部被跳过时返回可区分的本地错误及原因汇总，不绕过规则强行使用最后一个供应商。阈值暂停全部候选时可映射 HTTP 429，全部因数据待确认而跳过时可映射 HTTP 503；混合已有失败原因时沿用聚合规则并保留逐供应商原因。重试时间仅在可合理计算时附带，不把预计重置时间承诺为恢复时间。

## 数据与契约

供应商配置增加两个可空字段，分别对应实际短窗和长窗：

```text
oauth_short_window_stop_percent: integer | null
oauth_long_window_stop_percent: integer | null
```

`null` 表示对应规则关闭，不额外持久化重复的总开关。供应商 CRUD、编辑表单、复制、配置导入导出和生成的 IPC 类型一并更新；API Key 模式下规则不生效，前后端校验口径一致。运行时快照留在本地，不随供应商配置导出。

在现有快照表上增加短窗 / 长窗的 `remaining_percent REAL NULL`，保留显示文本、重置时间及 `checked_at`。刷新调度另存最后尝试时间、刷新错误和下次重试时间，失败不修改 `checked_at`。需要显式区分成功返回但不支持百分比，与刷新失败导致数据未知。

- 适配器返回结构化百分比和窗口信息；百分比为有限数值，范围 0–100，比较前不取整。
- Codex / Claude 从上游用量原始值换算；Gemini 有 `remainingFraction` 或可靠的剩余量 / 总量时计算百分比，即使界面优先显示次数也需保留百分比。只有次数且无总量时返回空值，不能把“7 次”解释为 7%。
- Gemini 第一版延续供应商级窗口聚合；各桶的百分比必须与其窗口及重置时间一起归组，再取该窗口最小值，不独立排序重置时间后拼接。该方案可能因某模型额度低而暂停整个供应商，界面需要说明此聚合口径。
- 老快照的结构化数值迁移为 `null`，等待重新获取，避免把已取整文本反推成准确值。未配置规则仍保留现有耗尽拦截兼容性。
- 查询、写入及后台任务必须防止账号更换、删除供应商、停止网关后迟到的查询结果覆盖新状态；所有入口共用去重及账号版本校验。真实耗尽事件不得被更早开始、稍后完成的旧额度查询覆盖。

`OAuthLimitGate` 返回 `Allow / Limited / Threshold / Unverified`，区分 `threshold_reached`、`quota_exhausted`、`quota_unverified`。`OAuthQuotaState` 提供规则、原始百分比、快照时间、预计重置时间和最后刷新错误。后台判断、请求判断和前端状态读取复用同一决策函数。

## 实施顺序与验收

1. 结构化额度解析、配置字段、数据库迁移及 IPC 契约。
2. 共享额度服务、后台刷新、去重、退避及任务生命周期。
3. 统一门禁结果与请求跳过原因，覆盖 HTTP、WebSocket 和桥接源供应商。
4. 编辑窗口、供应商卡片、首页额度状态和刷新反馈。

验收覆盖：等于阈值、原始精度边界、双窗任一命中、关闭及 0% 规则、缺失或过期数据、刷新失败、重置到期待确认、调低 / 调高阈值、账号切换、迟到结果、Gemini 次数与百分比区分、暂停期间继续轮询、全部供应商受限及故障转移、WebSocket 后续请求、流不中断和源供应商约束。

实现时执行必要的前端类型 / 契约检查和相关 Rust / 前端测试，按阶段使用中文 Conventional Commits 提交。遵守仓库约定，启动服务器及视觉验证另需用户明确许可。
