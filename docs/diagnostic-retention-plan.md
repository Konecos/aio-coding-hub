# 通信信息驻留实现计划

## 使用流程

- 在最近代理记录旁增加“信息驻留”开关和“通信查看”入口。
- 默认关闭；开关和驻留天数写入本地，默认 15 天，允许 1–365 天。
- 开启后采集新请求的客户端请求、供应商请求、供应商响应、客户端响应，按 trace_id 关联。查看器每秒刷新，可暂停查看、按请求选择并复制信息；日志详情提供同一请求的通信入口。
- 关闭只停止采集，已有内容继续可查；清空会使进行中的旧采集句柄失效，避免清空后重新写回。

## 存储及链路

- 使用应用数据目录中的独立 SQLite 数据库，避免正文进入常规请求日志、统计或配置同步。
- 专用写入线程通过有界队列接收数据；代理链路不等待磁盘，不改变流式传输、错误、取消或响应头行为。队列拥塞时明确报告丢失的数据。
- 按请求分组保留，单条通信正文最多 64 KiB，每请求最多 64 条通信，总正文及元数据最多 50 MiB、最多 1000 个请求。达到上限删除最旧请求；过期清理在启动、读写以及修改驻留天数时执行。
- 认证、Cookie 及敏感头字段脱敏，URL 隐去查询值；正文可能包含提示词和代码，在开关附近明确说明。二进制、压缩正文标明编码，不伪装成可阅读 JSON。
- 通过流包装采集，保持分块内容、错误和 HTTP trailers。供应商响应在统一响应封装处采集，包含重试失败响应和 Responses WebSocket 响应。

## 验证

- 后端验证默认设置、持久化与重启读取、驻留清理、容量约束、清空/关闭后的迟到数据、脱敏、流内容及错误透传。
- 前端验证开关及天数保存、实时查看/暂停、失败反馈和详情关联。
- 执行类型检查、相关单元测试、Rust 检查及格式检查。遵守仓库要求，不启动服务器、不做视觉验证。各阶段使用中文 Conventional Commit 提交。

## 实现结果

- 本地数据库：`gateway-diagnostics.sqlite3`，开关及驻留天数在应用启动时恢复。每分钟维护过期数据和数据库空闲页，读取/写入及设置修改时同时检查留存与容量。
- 首页“信息驻留 / 通信查看”和代理记录详情“查看驻留通信”已经接入。选中的请求不会随着新请求到来而跳转。
- HTTP 正文保留分块与 trailers；Responses WebSocket 请求在转换成实际 `response.create` 消息后采集，供应商响应在统一响应封装处采集。认证头、Cookie、URL 凭据和查询值隐藏；二进制正文以 Base64 展示。
- 清空及缩短驻留时间会清除前端正文缓存，并重新读取数据库；清空或关闭后到达的旧通信不会重新驻留。
- 已通过 66 项前端测试和 9 项后端驻留测试；类型检查、前端 lint、时钟订阅检查及 Rust 编译检查通过。最后修改发送采集时机后再次执行后端测试。
- 容量统计按原始正文和 UTF-8 元数据的字节数计算，包含中文等多字节文本的边界测试；生成 IPC 契约一致性校验通过。
